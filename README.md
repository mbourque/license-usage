# License Usage Tools

Tools for analyzing PTC Creo / FlexLM license usage from `ptc_d` server logs.

## What this answers

From a historical `ptc_d.log`:

- How many licenses were in use at once (**peak concurrent**)
- Whether anyone was blocked (**DENIED** — `Licensed number of users already reached`)
- Which users and days saw denials

Owned-seat files (`ptcstatus`) are optional. Without them, the report is usage-only (peak concurrent + denials).

## Requirements

- Python 3
- No third-party packages required for `license_usage2.py`

Optional local venv:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

## Main script: `license_usage2.py`

Stage 1 text report. Edit defaults at the top of the file, then run:

```powershell
.\venv\Scripts\python.exe license_usage2.py
```

Or with CLI overrides:

```powershell
.\venv\Scripts\python.exe license_usage2.py --log_file "C:\path\to\ptc_d.log" --licenses "" --lookback_days 0 --reporting_days 0
```

### Important defaults

| Setting | Meaning |
|---|---|
| `DEFAULT_LOG_FILE` | Path to `ptc_d.log` |
| `DEFAULT_STATUS_FILE` | Optional `ptcstatus` dump; blank = usage-only |
| `DEFAULT_LICENSES` | Features to analyze, `\|`-separated; **blank = all features** |
| `DEFAULT_LOOKBACK_DAYS` / `DEFAULT_REPORTING_DAYS` | `0` = entire log |
| `DEFAULT_USERS` | `user@host` filter; blank = all users |
| `DEFAULT_CAPACITY` | Optional `Feature=N\|Feature2=M` owned counts |

Use `--prompt` for interactive prompts instead of defaults.

### How concurrent use is counted

- Concurrent seats = **unique `user@host`** holding a feature
- Same user launching Creo again on the **same host** still counts as **1 seat**
- Different hosts for the same username count as separate seats
- Counts reset on `Server started` lines in the log

### How to read the report

- **Peak concurrent in use** — highest number of unique holders at once (best “how many seats they used” figure)
- **Triggered by checkout** — the user whose OUT raised the unique count to that peak (not the only user)
- **Saturation denials** — real FlexLM refusals when seats were exhausted (retry bursts in the same second are collapsed to one event)
- Denials are stronger proof of shortage than peak alone; unmatched OUT/IN can still skew peaks slightly

## Data files (local, usually gitignored)

| File | Role |
|---|---|
| `ptc_d.log` / `ptc_d.log.*` | FlexLM vendor daemon log |
| `ptcstatus_output.txt` | Snapshot from `ptcstatus` (optional; may be sample/edited) |
| `license_usage.csv` | Generated by live snapshot tooling if present |

Do not commit large logs or generated status/CSV outputs (see `.gitignore`).
